## 1. 기술 스택

| 계층 | 기술 |

## 2. 문서 처리 파이프라인

```
업로드 → UPLOAD(파일 수신) → 파싱(hwpx/docx/pdf 어댑터: 텍스트+표+그림, bbox/block_type)
→ 청킹(문자 기준 또는 semantic) → 임베딩(e5-large) → Qdrant 업서트 → INDEXED
→ (fire-and-forget) generate_summary + extract_metadata
```

- 처리 단계별 `processing_jobs` 레코드로 진행 상황을 UI에 노출.
- INDEXED 전환 시 요약(`summary_status`)과 추천 태그(`metadata_status`) 태스크가
  동일 관례(PENDING→GENERATING→DONE|FAILED)로 병렬 발행됨.
- 재임베딩(reembed) 태스크로 모델 교체 시 기존 청크 재처리 가능.

## 3. 검색

`POST /api/v1/search` — 요청: `{query, collection_id?, project_id?, limit, mode, diversify, filters?}`

1. **쿼리 재작성**: `expand_query()` — SEARCH_EXPAND 동의어 사전 기반, 원쿼리에 확장어 덧붙임.
2. **임베딩**: 확장된 쿼리를 e5-large로 벡터화 (`asyncio.to_thread`, 이벤트 루프 보호).
3. **권한 스코핑**: collection_id 미지정 시 사용자 접근 가능 컬렉션으로 강제 제한.
4. **Qdrant 검색**: disabled 청크 제외. hybrid는 limit×4, diversify는 limit×3 후보 확보
   (diversify 시 벡터 동반 반환).
5. **hybrid 모드**: BM25(kiwipiepy 토큰화) 점수와 벡터 점수를 0.4:0.6 융합.
6. **diversify 모드**: greedy MMR(λ=0.7)로 중복 억제 후 최종 limit개 선택.
7. 응답: `{items[], expanded_query, added_terms[]}`. 검색 이력은 원본 쿼리로 기록.

## 4. 검색 사전 (관리자)

- 테이블: `dictionary_entries` + `dictionary_entry_variants`.
- 유형: 불용어(match_type 5종) / 동의어(방향 2종 × 처리방식) / 사용자 사전(processing_rule).
- 검색 반영 지점 2곳:
  - **BM25 토큰화**: 불용어 필터, 동의어/별칭 → 대표어 확장 (모든 동의어 대상)
  - **쿼리 재작성**: `SEARCH_EXPAND` 처리방식 항목만 임베딩 쿼리 자체를 확장
- 저장 즉시 `refresh_dictionary_cache()`로 인메모리 캐시 재구축 (Kiwi 재빌드 포함).
- 엑셀 일괄 업로드/다운로드 지원 (`문서_처리_사전_스키마.md` §6 형식).

## 5. 메타데이터 (추천 태그)

- `Document.tags` (사용자 관리, Qdrant 청크 payload에 동기화)와
  `Document.suggested_tags` (LLM 제안, DB 전용)를 엄격 분리.
- 수락: `POST /documents/{id}/tags/accept-suggestion` → tags 승격 + Qdrant 동기화.
- 무시: `POST /documents/{id}/tags/dismiss-suggestion` → 제안만 제거.
- 추출 품질 가드: 한자 비율 필터, 기존 태그 제외, 중복 제거, 10개 상한, 100자 상한.

## 6. 인증/권한

- JWT access token + httpOnly refresh cookie. 역할: admin/editor/viewer + 컬렉션 멤버십.
- 모든 검색·문서 접근은 `accessible_collection_ids` / `check_document_access`로 스코핑.
- BYOK: 사용자별 OpenAI/Anthropic API 키 (채팅용), 사용량 대시보드 제공.
