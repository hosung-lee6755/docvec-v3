# error_codes.md
# Document Vectorization Platform - Error & Warning Code Catalog

## 1. 문서 목적

본 문서는 파이프라인 전반에서 발생할 수 있는 모든 에러 및 경고 코드를 정의한다.
각 코드는 카테고리, 심각도, 메시지, 원인, 권장 대응으로 구성된다.

---

## 2. 코드 체계

### 2.1 형식

```
{CATEGORY}_{SEVERITY}_{SEQUENCE}
```

| 요소 | 설명 | 예시 |
|------|------|------|
| CATEGORY | 발생 범주 (3–6자 대문자) | `PARSE`, `OCR`, `EMBED` |
| SEVERITY | 심각도 (`E`=Error, `W`=Warning, `I`=Info) | `E`, `W` |
| SEQUENCE | 3자리 순번 | `001` |

예: `PARSE_E_001` — 파싱 에러 001번

### 2.2 심각도 정의

| 심각도 | 의미 | 파이프라인 영향 |
|--------|------|----------------|
| `E` (Error) | 처리 중단 필요 | 해당 스테이지 실패, 작업 FAILED 상태 |
| `W` (Warning) | 처리 계속 가능하나 품질 저하 | 처리 계속, diagnostics에 기록 |
| `I` (Info) | 참고 사항 | 처리 계속, 로그에만 기록 |

## 15. HWP/HWPX 페이지 재분할 — Best-Effort 오류 처리 패턴

`_repaginate_hwp_like()` 함수는 HWP/HWPX 문서의 LibreOffice 미리보기 PDF 기반 실제 페이지 경계 복원을 수행한다.
이 과정에서 실패(PDF 생성 오류, 텍스트 매칭 실패)가 발생하면:

1. `logger.exception()` 으로 상세 로그 기록
2. 파이프라인 **계속 실행** (전체 parse_document 태스크 실패하지 않음)
3. 해당 청크의 `page_number` 을 기본값 1 로 유지
4. RAG 인용에서 페이지 정보가 손실되지만 처리는 진행

**설계 철학:** 불완전한 페이지 정보가 있는 것이 페이지 정보가 없는 것보다 낫다.
예방 가능한 오류(네트워크 지연, 임시 리소스 부족)는 사용자 재시도로 복구 가능.

## 15. WARN_OCR_DEPENDENCY_HIGH (특수 코드)

```
WARN_OCR_DEPENDENCY_HIGH
```

전체 문서에 대해 발생하는 단일 경고 코드. OCR 신뢰도 0.5–0.7 범위의 페이지가
전체의 일정 비율을 초과할 때 diagnostics에 포함된다.

- 임계값: `quality.ocr_dependency_warn_threshold` (기본 0.3)
- 처리: 파이프라인 계속 실행
- 위치: `RawParsedDocument.parse_warnings` 및 `diagnostics.json`
