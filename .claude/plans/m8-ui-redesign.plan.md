# Plan: UI/UX 전면 개편 (v3 마일스톤 8)

**Source PRD**: `.claude/prds/agentic-rag-governance-v3.prd.md`
**Selected Milestone**: 8 — UI/UX 전면 개편 (v2 #5)
**Complexity**: Large

## Summary
30개 화면 전부를 새 디자인 체계로 옮긴다. 사용자 화면은 B안(밝은 중립형, 사이드바, 흰 카드, 조밀한 표, 옆 패널)을 기본으로 하고, 관리 화면은 C안의 구성(요약 숫자 띠, 일괄 선택 막대, 문제 행 강조)을 섞는다. KRDS는 유지하되 KRDS의 색 단계 변수를 새 색상 조합으로 다시 정의해 KRDS 컴포넌트도 같은 색을 쓰게 한다. 시안은 https://claude.ai/artifact/E8c1bgYHGKydYKqtEe2iaQ (3행: 새 색상 조합, B+C 혼합 문서 관리).

## 사용자 결정 (2026-11-12)
- KRDS 유지하고 정리. 지금 디자인은 마음에 들지 않음 → 기업용 SaaS 느낌으로.
- 범위는 30개 화면 전부.
- B안 기본 + 관리 화면은 C안 구성. 색상 조합은 새로.
- 브라우저 화면 점검은 개편이 끝난 뒤 마일스톤 1~8 전체를 한 번에.

## 기본값
1. 글꼴은 KRDS에 들어 있는 Pretendard GOV(subset woff2)를 `@font-face`로 직접 싣는다. 외부 글꼴 서버를 쓰지 않는다(망분리 대응).
2. 색은 `styles/tokens.css` 한곳에서 정한다. 기존 변수 이름(`--color-text-muted` 등)은 유지하고 값만 새 색으로 바꿔 1,600곳의 기존 사용처가 바로 따라오게 한다. 새 이름(`--color-primary`, `--color-status-*`, `--color-level-*`)을 더한다.
3. KRDS 기본 단계 변수(`--krds-color-light-primary-*`, `gray-*`, `danger-*`, `warning-*`, `success-*`, `information-*`)를 새 색에 맞춰 다시 정의한다. KRDS 파일은 고치지 않는다.
4. 공통 컴포넌트는 `components/ui/`에 둔다: Button, IconButton, Field(Input, Select, Textarea), Badge(tone), StatusBadge, SecurityLevelBadge, Card, PageHeader, Toolbar, FilterChip, DataTable 클래스, SidePanel, BulkActionBar, StatStrip, EmptyState, Tabs, Modal. 스타일은 `styles/components.css`의 `ds-*` 클래스로 두어 hover, focus, active 상태를 CSS로 처리한다.
5. 레이아웃: 밝은 사이드바(프로젝트 전환, 찾기와 바로가기 Ctrl K, 메뉴 묶음, 사용자와 열람등급), 오른쪽은 회색 바탕 위 흰 카드 틀.
6. 하드코딩한 색 약 500곳은 토큰으로 바꾼다. 같은 의미의 Tailwind 계열 색(#dc2626, #e2e8f0 등)은 대응 토큰으로 일괄 치환하고, 화면을 옮길 때 남은 것을 정리한다.
7. 관리 화면(문서 관리, 사용자, 그룹, 원천 연결, 토큰, 감사 로그, 답변 추적, 사용량, 처리 현황)은 StatStrip과 BulkActionBar를 쓴다. 기존 API로 할 수 있는 일괄 동작만 넣는다(새 백엔드 API는 만들지 않는다).
8. 어두운 테마는 이번 범위에서 뺀다.
9. 동작은 바꾸지 않는다. 기존 테스트가 쓰는 접근성 이름(role, label 문구)은 유지한다.

## 단계
1. 기반: 토큰, 글꼴, KRDS 변수 재정의, 공통 컴포넌트, 레이아웃, 하드코딩 색 일괄 치환.
2. 사용자 화면: 채팅, 검색, 문서 목록, 문서 상세, 컬렉션, 프로젝트와 워크스페이스, 대시보드, 로그인과 가입, 설정.
3. 관리 화면: 사용자, 그룹, 원천 연결, 외부 에이전트 토큰, 감사 로그, 답변 추적, AI 기본법 근거 자료, 사용량, 처리 현황.
4. 파이프라인 화면: 워크플로우 목록, 편집기, 실행 기록, 검색 사전, 정제 규칙.
5. 정리: 남은 인라인 색, 사용하지 않는 CSS, 문서 갱신, 전체 브라우저 점검(마일스톤 1~8).

## 결과 (2026-11-12)

브라우저 점검은 관리자 계정으로 사이드바 21개 경로와 그 안의 탭, 모달, 상세 패널, 필터를 직접 눌러 확인했다.
삭제, 회수, 저장 같은 되돌릴 수 없는 동작은 확인 단계까지만 눌렀다. 화면마다 `h1`이 하나인지, 문서가 화면 높이를
넘지 않는지, 오류 알림이 없는지는 21개 경로를 차례로 열어 일괄 확인했다.

점검 중 고친 것은 다음과 같다.

- KRDS 전역 규칙이 화면을 해친 곳: 체크박스 숨김, 표 고정 배치, `legend` 숨김, 마우스 클릭에도 남는 두꺼운 초점
  테두리, `code`의 역슬래시가 ₩로 보이는 글꼴. 모두 `krds-theme.css`에서 되돌렸다.
- 숨김 캡션이 스크롤 영역 밖으로 빠져 문서 높이를 늘리던 문제: `.ds-main__frame`, `.ds-table-wrap`을 위치 기준으로 했다.
- 문서 목록: 필터 결과가 0건이면 "조건에 맞는 문서가 없습니다"와 초기화 단추를 보인다. 상태와 컬렉션 필터를
  화면에서 바꾸면 URL도 바뀌어 사이드바 강조와 새로고침 결과가 맞는다.
- 역할 표기가 화면마다 '뷰어'와 '조회자'로 갈라져 있던 것을 `lib/roleLabels.ts`로 모으고 '조회자'로 맞췄다.
- 답변 추적: 역할과 열람등급을 한글로, 토큰과 응답 시간을 "토큰 기록 없음 · 63.9초"처럼 보인다.
- 워크플로우 실행 기록: 요약 띠에 "검토 대기"를 더해 합계가 맞게 했다. 대상 문서가 없는 실행은 403 안내를 보인다.
- 원천 연결 상세: 340px 패널 안 표의 여백을 줄였고, 보류 파일의 사유를 아랫줄로 내렸다.
- 설정: 외부 에이전트 카드를 다른 설정 카드와 같은 틀로 바꾸고, 탭에 `aria-current`를 붙였다.
- 로그인과 가입: 부제목으로 두 화면을 구분하고, 관리자 코드 토글을 링크형 단추(`aria-expanded`)로 바꿨다.
- 860px 이하에서는 사이드바 메뉴를 접고 "메뉴" 단추로 펼친다.

동작이 바뀐 것은 다음과 같다.

- 모달은 Esc로 닫히고, 취소하면 입력값이 지워진다.
- 현재 페이지에서만 센 요약 숫자에는 "이 페이지"를 붙였다.

남은 결정(개편 전부터 있던 동작이라 고치지 않았다):

- 컬렉션 만들기 모달의 "기본 보안등급"은 화면에만 있고 요청에 실리지 않는다. 필드를 없앨지 API에 넣을지 정해야 한다.
- 대상 문서가 없는 워크플로우 실행(삭제된 문서 등)의 상세는 백엔드가 403을 준다. 관리자에게 보여 줄지 정해야 한다.
- 검토용 임시 컨테이너로 직접 접속하면 `/artifacts`를 중계하는 Caddy를 거치지 않아 PDF 미리보기를 확인하지 못했다.
  화면 문제가 아니라 점검 환경의 한계다. Caddy를 거치는 실제 접속 경로에서 한 번 더 보면 된다.
