## 1. 프로젝트 개요와 v3 범위

DocVec v3는 문서를 올리면 사용자의 권한에 맞춰 검색하고, 근거를 붙여 답하는 플랫폼이다. v2의 전처리 파이프라인(PDF, DOCX, HWP, HWPX 처리, 워크플로우 편집기, 하이브리드 검색, RAG 채팅)을 이어받았다. 그 위에 v3 PRD(`.claude/prds/agentic-rag-governance-v3.prd.md`)에 따라 권한 모델, 답변 추적과 AI 기본법 근거 자료, 사내 AD 로그인과 파일 서버 연결, 외부 에이전트용 MCP 서버, 옵트인 심층 검색, 문서 버전 수명주기와 골든 쿼리 평가, 새 디자인 체계를 더했다. v2 PRD에서 착수하지 않았던 마일스톤 2, 3, 5는 v3 PRD로 옮겨졌다.

| 마일스톤 | 내용 | 상태 (PRD 기준) |
|---|---|---|
| 0 | 저장소 분기, 개발 스택 분리(프로젝트명 `project_3`, 포트 +10000) | 완료 |
| 1 | 권한 모델 확장(그룹, 보안등급, 문서별 허용). 누출 매트릭스 43건 통과 | 완료 |
| 2 | 거버넌스와 감사 증적(답변 추적, AI 기본법 근거 자료) | 완료 |
| 3 | 사내 계정(AD) 로그인과 파일 서버(SMB) 커넥터 | 완료 |
| 4 | 외부 에이전트 연동(MCP)과 개인 접근 토큰 | 완료 |
| 5 | 심층 검색(질문을 나눠 찾는 에이전틱 검색, 옵트인) | 완료 |
| 6 | 문서인식과 검색 품질 노출 UI | 완료 |
| 7 | 문서 버전 수명주기와 골든 쿼리 회귀 평가 | 완료 |
| 8 | 전체 화면의 새 디자인 체계 | 완료 |

마일스톤 완료 뒤에도 후속 작업이 이어졌다(커밋 순서 기준). 먼저 검토 대기와 실패 화면, 원인을 알려 주는 오류 문구, 계정 발급, 서버 로컬 폴더 커넥터, AD 사전 등록, 그룹 권한 이어받기, 암호화 키 교체, 배포 점검, 전처리 성능 개선(GPU 작업 분리, 쪽 번호 귀속 수정, 표와 청크 개선), 하이브리드 키워드 색인, 새 문서 형식, 알림, 답변 스트리밍(SSE), HWPX 표 개선, OIDC 로그인, 백업과 지표 같은 운영 기반이 들어갔다. 2026-11-17에는 표 질문의 검색 경로 수정, 품질 경고 대상 표시, 구형 HWP 표와 서식, 제목 상자 인식, 로컬 그림 모델 연동을 마쳤다. 자세한 구현 결과는 9절과 `docs/design/시스템_전체_점검_및_고도화_방안_2026-11-16.md` 9절에 있다.

## 2. 기술 스택과 구성

| 계층 | 기술 |
|---|---|
| 백엔드 | FastAPI(API는 async, 워커는 sync 세션), SQLAlchemy, Pydantic, Alembic |
| 비동기 작업 | Celery와 Redis. 큐는 `critical`, `high`, `normal`, `low`, `embed`, `llm`, `extract` 일곱 개다. beat가 30초마다 워크플로우 sweeper를 돌린다. |
| 저장소 | PostgreSQL(문서 메타데이터, 권한, 감사 기록), Qdrant(청크 벡터, 키워드 색인, 요약 벡터), MinIO(원본과 미리보기), Redis(작업 큐, 답변 캐시, 호출 제한) |
| AI | 임베딩 BGE-M3, 재순위 bge-reranker-v2-m3, 로컬 LLM Qwen2.5 3B와 7B(Ollama, 4비트 양자화). 외부 모델(OpenAI, Anthropic)은 보안등급이 허용하는 문서에만 쓴다. |
| 문서 파서 | 형식마다 어댑터가 나뉘어 있다(`backend/app/pipeline/adapters`). PDF는 Docling과 EasyOCR, HWP는 pyhwp, HWPX는 XML을 직접 읽고, XLSX, PPTX, 이미지, 텍스트는 각각 전용 어댑터를 쓴다. |
| 프런트엔드 | React 18.3, Vite 6, TypeScript, Vitest와 React Testing Library |
| 인프라 | Docker Compose(프로젝트명 `project_3`), Caddy 2.8.4(HTTPS 리버스 프록시, 자체 서명 인증서), GPU 1장(12GB) |

주요 디렉터리는 다음과 같다. `backend/app/{api, core, db, pipeline, services, mcp}`, `backend/tests`, `backend/alembic`, `backend/scripts`, `frontend/src/{pages, components}`, `caddy/Caddyfile`, `docker-compose.yml`, `scripts/`(백업, 복원, E2E 스모크), `docs/`.

## 3. 서비스 구성, 포트, 워커 큐

Compose에는 13개 서비스가 있다. 호스트 포트는 모두 `127.0.0.1`에만 열고, 외부에 열린 서비스는 Caddy뿐이다.

| 서비스 | 역할 | 호스트 포트 |
|---|---|---|
| `caddy` | HTTPS 리버스 프록시. 외부 노출의 유일한 입구다. 13080(HTTP)으로 들어오면 13443으로 넘긴다. | 13443(HTTPS), 13080(HTTP) |
| `api` | FastAPI 앱 서버 | 127.0.0.1:18001 |
| `frontend` | React 정적 빌드(nginx). Caddy를 거쳐 접속한다. | 없음 |
| `postgres` | 메타데이터 DB | 127.0.0.1:15433 |
| `redis` | Celery 브로커와 백엔드, 캐시, 호출 제한 | 127.0.0.1:16380 |
| `qdrant` | 벡터 DB | 127.0.0.1:16335(HTTP), 16336(gRPC) |
| `minio` | 오브젝트 스토리지 | 127.0.0.1:19002(API), 19003(콘솔) |
| `llm` | 로컬 LLM 추론 서버(Ollama 0.40.12). 요청이 오면 모델을 올리고 10분 쉬면 내린다. | 없음(내부 네트워크) |
| `worker` | 일반 블록 워커. `critical`, `high`, `normal`, `low` 큐, 동시 4개, 자식 프로세스 메모리 4GB 초과 시 교체 | 없음 |
| `worker-embed` | GPU 작업 워커. `llm`, `embed` 큐, 동시 1개 | 없음 |
| `worker-extract` | 텍스트 추출 워커. `extract` 큐, 동시 1개, 자식 프로세스 메모리 8GB 초과 시 교체 | 없음 |
| `beat` | Celery 주기 작업(워크플로우 sweeper 30초, 답변 추적 정리 하루 한 번) | 없음 |
| `flower` | Celery 모니터링 화면. `FLOWER_BASIC_AUTH`가 필요하다. | 127.0.0.1:15556 |

워크플로우 블록은 GPU 사용 여부에 따라 큐가 갈린다(`backend/app/pipeline/tasks/workflow.py`의 `step_queue_for_block`). `text_extract`는 `extract` 큐로 가고, 임베딩과 LLM을 쓰는 `rag_store`, `summarize`, `extract_keywords`, `classify`, `extract_entities`, `output`과 의미 기반 청크 분할(`chunk_split`의 `strategy=semantic`)은 `embed` 큐로 간다. 나머지 블록은 `normal` 큐로 간다. GPU 블록을 새로 만들면 `_GPU_BLOCK_TYPES`에 넣는다. 일반 워커에서 GPU 모델이 돌면 프로세스마다 모델 사본이 올라가 GPU 메모리가 경합하고 문서가 실패한다.

## 4. 운영 환경

현재 운영은 GPU 12GB 한 장을 갖춘 서버 PC 한 대에서 Docker Desktop으로 돈다. Project_2가 같은 PC에서 떠 있다면 두 스택의 GPU 워커(`worker-embed`, `worker-extract`)를 동시에 올리지 않는다. CUDA 메모리가 경합해 문서가 실패하거나 Docker VM 전체가 멈출 수 있다.

외부 접속은 Caddy의 HTTPS 포트 하나로 한다. 공유기에서도 이 포트만 포워딩한다. 원본 파일 주소는 MinIO를 상대 경로로 중계하므로(`MINIO_RELATIVE_URLS=true`), 사내와 외부 어느 주소로 접속해도 원본이 열린다. 접속 주소가 바뀌면 `caddy/Caddyfile`의 사이트 주소와 `.env`의 `CORS_ALLOWED_ORIGINS`, `MINIO_PUBLIC_ENDPOINT`를 함께 고친다. 자세한 절차는 가이드 1.9절에 있다.

## 5. 처음 띄우기

1. **`.env` 준비.** `.env.example`을 `.env`로 복사하고 값을 채운다. Compose 파일은 `SECRET_KEY`, `ENCRYPTION_KEY`, `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `MINIO_ROOT_USER`, `MINIO_ROOT_PASSWORD`, `FLOWER_BASIC_AUTH` 가운데 하나라도 비어 있으면 기동을 거부한다. `ENVIRONMENT=production`이면 앱도 기본 `SECRET_KEY`와 빈 `ENCRYPTION_KEY`를 거부한다.
2. **기동.** `docker compose -p project_3 up -d`. Compose 파일이 프로젝트명을 `project_3`으로 정해 두었으므로 `-p`는 생략해도 되지만, 명령을 적을 때는 명시한다.
3. **임베딩과 재순위 모델 받기.** 최초 1회만 한다. `docker compose -p project_3 exec worker-embed poetry run python -m app.pipeline.download_models`. 모델은 `HF_HOME=/model_cache` 볼륨에 남는다.
4. **LLM 모델 받기.** `docker compose -p project_3 exec llm ollama pull qwen2.5:3b-instruct-q4_K_M`을 실행한다. 받아 두지 않은 모델은 채팅 화면에서 "사용 불가"로 보인다. 7B(`qwen2.5:7b-instruct-q4_K_M`)는 같은 방식으로 받으며, 대량 추출과 겹치면 12GB GPU를 넘을 수 있다(설계 문서 9.3절과 9.4절).
5. **첫 관리자 계정.** 회원가입 화면에서 `.env`의 `ADMIN_SIGNUP_CODE`를 입력하면 admin으로 가입한다. AD 로그인을 켜면 회원가입을 받지 않는다. 시스템 계정 `system@docvec.internal`은 비활성 상태이며 시스템 워크플로우의 소유자로만 쓰인다.
6. **건강 확인.** `docker compose -p project_3 ps`로 13개 서비스가 실행 중인지 본다. `http://127.0.0.1:18001/openapi.json`이 200을 돌려주는지 확인한다. 앱에서 소형 PDF를 올려 문서 상세의 처리 단계가 INDEXED까지 가는지, 원문 대조 탭과 인용 위치 표시가 열리는지 본다.

화면 접속 주소는 `caddy/Caddyfile`의 사이트 주소와 맞아야 한다(4절 참고). 자체 서명 인증서를 쓰므로 처음 접속할 때 브라우저 경고가 뜨는 것이 정상이다.

## 6. 매일 쓰는 명령

```bash
# 백엔드 코드 수정 후 (재시작만 하면 된다)
docker compose -p project_3 restart api worker worker-embed worker-extract beat

# 프런트엔드 코드 수정 후 (정적 빌드라 재빌드가 필요하다)
docker compose -p project_3 build frontend && docker compose -p project_3 up -d frontend

# Caddyfile 수정 후
docker compose -p project_3 restart caddy

# .env나 compose 파일을 바꾼 뒤 (재생성해야 반영된다)
docker compose -p project_3 up -d <서비스>

# 로그
docker compose -p project_3 logs -f worker-extract worker-embed --tail 200
```

운영 명령 전체, 장애 대응, DB 접근, 테스트 실행은 `docs/유지보수_가이드.md` 1부에 있다.

## 7. 인수인계 시 별도로 받아야 하는 것 (레포에 없음)

- [ ] `.env` 전체. `SECRET_KEY`, `ENCRYPTION_KEY`, `POSTGRES_*`, `MINIO_ROOT_*`, `FLOWER_BASIC_AUTH`, `ADMIN_SIGNUP_CODE`를 포함한다. 지표 수집기를 쓴다면 `METRICS_TOKEN`도 필요하다.
- [ ] **`ENCRYPTION_KEY`는 바꾸지 말 것.** 저장된 BYOK API 키가 이 키로 암호화돼 있어, 바꾸면 복호화할 수 없다. 교체가 꼭 필요하면 `backend/scripts/rotate_encryption_key.py`와 가이드 1.19절의 절차만 쓴다.
- [ ] AD 로그인을 쓴다면 바인드 계정과 비밀번호, OIDC를 쓴다면 클라이언트 ID와 비밀값. 둘 다 `.env`에만 둔다.
- [ ] 서버 PC 접속 방법, 공유기 관리자 정보(포트포워딩과 DHCP 예약 변경용), DDNS나 도메인 정보(있다면)를 전달받는다.
- [ ] 관리자 앱 계정과 MinIO, Postgres 접속 정보를 전달받는다. MCP 개인 접근 토큰은 발급받은 사람이 각자 관리한다.
- [ ] git 원격 저장소 접근 권한을 받는다. 원격 주소는 `git remote -v`로 확인한다.

CI 정의는 `.github/workflows/ci.yml`에 있다. 백엔드는 API 이미지를 빌드해 테스트를 돌리고, 프런트엔드는 타입 검사, 린트, 단위 테스트, 프로덕션 빌드를 돌린다. 다만 이 워크플로가 GitHub에서 실제로 실행된 기록은 아직 확인하지 못했다.

## 9. 2026-11-16 점검 이후 구현 상태

`docs/design/시스템_전체_점검_및_고도화_방안_2026-11-16.md`의 1순위와 2순위 과제를 구현했다. 상태는 다음과 같다.

**구현 완료**
- 키워드 색인을 별도 Qdrant 컬렉션(`<이름>_lex`)에 두고, 키워드로 찾은 청크를 벡터 후보 뒤에 더한다. 점수를 섞는 RRF 방식은 아니다.
- XLSX, PPTX, 이미지, TXT, MD, HTML 형식을 추가했다. 형식 목록은 `backend/app/pipeline/formats.py`에 있다.
- 골든 평가에 사실 재현율 채점을 붙였고, 답변별 피드백(좋아요, 싫어요)을 추적 화면과 연결했다.
- 메타데이터 작업 등록을 복구했다. 원인은 Celery `include` 누락이었다.
- 이름, 주소, 운전면허, 여권을 탐지한다(문맥으로 찾는 이름 포함). 사업자등록번호는 기본 탐지에서 빼고 설정에서 골랐을 때만 찾는다.
- 원문 PDF 위에 근거 영역을 표시한다(글자 층이나 좌표가 있는 문서에 한한다). 글자 층이 없는 스캔본은 쪽만 보인다.
- 표의 병합 칸 위치를 저장해 원래 모양대로 그리고, 스캔 PDF의 표와 그림을 보존한다.
- `LLM_EXTRA_MODELS`로 코드 수정 없이 추가 로컬 모델이나 사내 OpenAI 호환 추론 서버를 더할 수 있다. 7B(`qwen2.5-7b`)는 기본 등록 목록에 있고, 2026-11-17에 실제로 돌려 보았다.
- 답변 스트리밍(SSE, `GET /chat/{id}/stream`). 스트림이 열리지 않으면 주기 조회로 돌아간다.
- 처리 실패, 검토 대기, 동기화 실패를 알리는 기능이 있다(`services/notifications.py`).
- 백업 스크립트는 실행해 확인했다(Postgres 덤프는 임시 DB에 복원해 확인했다). 지표는 `GET /api/v1/admin/metrics`에서 Prometheus 형식으로 나온다.
- 채팅과 MCP 응답에 AI 생성 표시를 붙인다. 설정 등급보다 높은 문서는 외부 모델로 보내지 않도록 차단한다(`EXTERNAL_MODEL_MAX_SECURITY_LEVEL`, 기본값 Internal).
- 제목 상자를 인식하고(`pipeline/blocks/title_box.py`), HWPX와 구형 HWP는 글자 크기와 굵기로 제목을 판정한다.

**부분 완료 또는 조건부**
- OIDC: 인가 코드 흐름과 PKCE를 구현했고 가짜 로그인 서버로 시험했다. 실제 IdP(Entra ID, Keycloak, Okta 등)에는 붙여 보지 않았다.
- 그림 설명: `LOCAL_VISION_MODEL`로 켜지만 기본값은 꺼짐이다. `qwen2.5vl:3b`는 같은 차트를 실행마다 다르게 설명해 수치를 지어낼 수 있다.
- GPU 상한: `GPU_MEMORY_FRACTION` 환경 변수는 워커 코드에 있으나 compose에는 넣지 않았다. 대량 처리 중에는 7B 답변을 쓰지 않는 쪽으로 운영한다.
- 호출 제한: Redis에 닿지 못하면 503으로 요청을 막는다(fail-closed). Redis 장애가 곧 서비스 중단이 된다는 뜻이다.
- 개요 스타일 기반 제목 판정은 아직 확인하지 못했다. 대신 제목 상자 방식으로 장 제목을 잡는다.

**구현하지 않았거나 확인하지 못함**
- SAML은 구현하지 않았다. 대상 로그인 서버가 OIDC를 지원하고 xmlsec 네이티브 라이브러리가 필요하다.
- MFA는 코드에 없다.
- 복원 스크립트(`scripts/restore.sh`) 전체는 운영 데이터를 덮어쓰므로 실행하지 않았다.
- GitHub에서 CI 실행은 확인하지 못했다.
- 답변 품질 평가는 사실 재현율까지만 있다. 충실도(답이 근거에 기대는 정도)를 재는 지표는 없다.

## 11. 작업할 때 꼭 지킬 것

1. **블록의 `run()` 로직을 바꾸면 `block_version`을 올린다.** 올리지 않으면 캐시 때문에 재처리해도 옛 결과가 나온다(가이드 2.4절). 현재 버전은 text_extract 1.26.0, structure_analyze 1.15.0, quality_check 1.7.0, chunk_split 1.7.0, rag_store 1.4.0, pii_detect 1.1.0, output 1.6.0이다.
2. **새 GPU 블록은 `_GPU_BLOCK_TYPES`에 넣는다.** 일반 워커에서 GPU 모델을 돌리지 않는다.
3. **캐시 안전 목록 `_CACHE_SAFE_BLOCK_TYPES`는 deny-by-default로 둔다.** 함부로 넣으면 재처리 뒤 탭이 비어 보인다(`pipeline/tasks/workflow.py`).
4. **`MINIO_RELATIVE_URLS=true`를 유지한다.** 끄면 원본 주소가 절대 주소가 되어 접속 환경에 따라 원본이 열리지 않는다.
5. **Caddyfile, compose 포트, `.env`를 바꿀 때는 외부에 열리는 포트가 늘지 않는지 확인한다.** DB, MinIO, Redis, Qdrant, API, Flower는 `127.0.0.1`에 둔다.
6. **새 마이그레이션 뒤에는 `alembic upgrade head`를 실행한다.** 현재 리비전은 64개다.
7. **테스트 일부는 실제 Postgres(`TEST_DATABASE_URL`)를 요구한다.** 운영 DB와 분리된 일회용 컨테이너를 쓴다(가이드 1.8절).
8. **프런트엔드는 정적 빌드라 수정 뒤 재빌드가 필요하다.** 핫리로드가 없다.
9. **호스트에는 Python이 없다.** 스크립트와 테스트는 컨테이너 안에서 실행한다(가이드 1.4절).
10. **한 GPU를 두 스택이 나눠 쓰지 않는다.** Project_2와 Project_3의 GPU 워커를 동시에 띄우지 않는다.
11. **커밋 전에 비밀값이 없는지, 전체 테스트가 통과하는지, 문서가 현재 구현과 맞는지 확인한다.** 커밋 메시지는 `<type>: <description>` 형식을 쓴다.
