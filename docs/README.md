# docs 폴더 문서 안내

프로젝트의 모든 문서는 이 폴더에서 관리한다. 처음 보는 사람은 `인수인계서.md`부터 읽는다.

> **v3 개발 저장소(Project_3)**: 이 저장소는 docvec-v2(Project_2) `1254b7a`에서 분기한 v3 개발본이다. 목표는 권한과 거버넌스가 내장된 에이전틱 RAG 플랫폼이며, Project_2는 운영과 데모의 기준점으로 동결해 버그 수정만 한다. 이 폴더의 문서는 2026-11-17 기준 v3 구현을 설명한다. 문서와 코드가 다르면 코드가 정본이다. 각 문서가 적은 기준 시점도 함께 확인한다. 개발 스택의 `docker compose` 프로젝트명은 `project_3`이고, 호스트 포트는 Project_2보다 10000 높다(웹 13443, API 18001 등, `.env.example` 상단 참고). 두 스택은 같은 PC에서 함께 띄울 수 있다. 다만 GPU 워커는 한 장의 GPU를 나눠 쓰므로 동시에 돌리지 않는다.

| 위치 | 내용 |
|---|---|
| `인수인계서.md` | 새 작업자가 가장 먼저 읽는 입구 문서다. 현황, 기동 방법, 보류 항목, 첫날 체크리스트를 담는다. |
| `유지보수_가이드.md` | 장애 대응, 운영 명령어, 외부 접속, 코드 확장 방법을 안내한다. |
| `기술문서_시스템_아키텍처.md` | 현재 구현이 어떤 알고리즘, 수식, 임계값으로 동작하는지 설명한다. |
| `design/` | **현행 설계서**다. 설계 의도와 화면, 데이터 구조를 담는다. 구현과 다른 부분은 "⚠ 실제 구현과 차이" 콜아웃으로 표시한다. |
| `design/메타 정보 생성.txt` | 문서와 청크의 메타정보 항목을 정의한다. 코드 주석의 "메타 정보 생성.txt N절"이 이 파일을 가리킨다. |
| `design/RAG_방식_분류_2026-11-17.md` | 현재 RAG를 작동 방식, 구현 도구, 데이터 저장소 기준으로 분류한 정의서다. 세부 알고리즘은 기술문서 11절에 있다. |
| `design/문서데이터 전처리 방안.md` | 전처리 단계(정제, 사전, PII, 구조, 청킹)의 기준 문서다. 모델과 블록 docstring이 § 번호로 이 문서를 참조한다. |
| `plan/` | **초기 기획과 상세 설계 자료**다(1. 구조 설계 ~ 7. 고도화 설계, 통합본 `MASTER_INTEGRATED_KO_UPDATED (1).md`). 최초 설계 시점의 기록 문서이며, 각 파일 상단에 "기록 문서 안내(2026-11-17)" 배너가 붙어 있다. 현행 구현과 다를 수 있으므로 구현 기준은 `design/`과 기술문서를 우선한다. |
| `참고/` | 보조 자료를 모아 둔 곳이다. 기술 브로셔(`DocVec_기술브로셔.html`), E2E 검증 보고서, 서버 접속 주소 메모가 있다. 메모에는 내부 IP가 포함되어 있어 저장소에는 올리지 않는다. |

문서 간 우선순위는 **현행 설계서(`design/`) > 기술문서 > 초기 기획(`plan/`)** 이다.

현행 문서(`design/`, 기술문서, 인수인계서, 유지보수 가이드)는 2026-11-17 시점의 코드를 기준으로 작성되었다. `plan/` 폴더의 문서는 기록으로만 읽고, 현재 동작을 판단하는 근거로 쓰지 않는다.
