# 전처리 워크플로우 화면 와이어프레임

**최종 갱신**: 2026-07-28 — 아래 내용은 실제 구현 완료 상태를 반영함

**작성일**: 2026-07-16
**상위 문서**: `전처리_워크플로우_통합_설계서.md` §9
**상태**: 구현 완료

공통 전제:
- 전체 레이아웃은 기존 `Layout.tsx`(좌측 사이드바 내비 + 콘텐츠 영역)를 유지한다. 아래 와이어프레임은 콘텐츠 영역만 그린다. 단, 좌측 대 메뉴의 구성은 §0에 따라 재편한다.
- 폼 컨트롤은 기존 KRDS 컴포넌트(`krds-input`, `krds-form-select`, `krds-form-check`)를 사용한다.
- `[버튼]` = 버튼, `(○/●)` = 라디오, `[x]` = 체크박스, `▾` = 드롭다운, `⚠` = 경고 배지, `●` = 상태 점.

## 0. 좌측 대 메뉴 재편 (정보 구조) — 2026-07-16 추가

기존 메뉴는 자원 유형 나열(대시보드/프로젝트/컬렉션/문서/검색/채팅/사전/워크플로우/관리)이라
"업로드 → 처리 → 검토 → 활용"이라는 실제 사용 흐름이 드러나지 않는다.
**사용 흐름 기준 4그룹**으로 재편한다.

```
┌──────────────┐
│ DocVec       │
│ 대시보드      │   ← 홈(요약)
│              │
│ 문서 처리     │   ← 매일 쓰는 흐름 (업로드→검토→모니터링)
│  문서        │      업로드·목록·상세
│  검토 대기 ⚠3 │      WAITING_REVIEW 큐 — 개수 배지 상시 표시
│  처리 현황    │      런/블록 모니터링 (§9 위젯)
│              │
│ 지식 활용     │   ← 처리 결과의 소비
│  검색        │
│  채팅        │
│              │
│ 구성         │   ← 가끔 만지는 설정 (처리 방식 정의)
│  프로젝트     │
│  컬렉션      │
│  워크플로우   │
│  사전        │
│  정제 규칙    │      신규 — cleaning_rules CRUD 진입점 (§3.3⑥)
│              │
│ 관리         │   ← 관리자
│  사용자      │
│  감사 로그    │
└──────────────┘
```

- **검토 대기**: 문서 목록의 WAITING_REVIEW 필터 프리셋 화면. 배지 수치는 폴링/이벤트로 갱신 — 검토 게이트가 흐름의 1급 단계임을 IA 차원에서 드러낸다.
- **처리 현황**: §9의 모니터링 위젯 페이지. 관리자 전용이 아닌 처리 담당자용이므로 "관리" 그룹이 아닌 "문서 처리" 그룹에 배치.
- **정제 규칙**: 신규 메뉴. 사전과 나란히 "구성" 그룹 — 둘 다 버전 관리되는 처리 자산.
- 구현 시 `Layout.tsx`의 `navItems` 배열에 그룹 라벨(section) 지원 추가 필요. `adminOnly` 속성은 "관리" 그룹에 적용.

```
├────────────────────────────────────────────────────────────────────────────────┤
│ 파일명              컬렉션    상태               품질          청크  수정일     │
│ ─────────────────────────────────────────────────────────────────────────────  │

│ 회의록_0710.docx    기획      ✕ FAILED (OCR_FAILED)            -   07-14 [재처리]│
│                                                                    ‹ 1 2 3 ›  │
└────────────────────────────────────────────────────────────────────────────────┘
```

- **상태 칼럼**: 17.3 상태 배지. 진행 중이면 `(현재블록 n/전체 블록)` 인라인 표시(런 스텝 집계).
- **품질 칼럼**: `quality_reports.overall_score` + 상태 라벨. 리포트 없으면(구버전 문서) `-`.
- WAITING_REVIEW 행: 행 강조 + `[검토]` 버튼 → 문서 상세 "품질" 탭 딥링크.
- FAILED 행: `[재처리]` 버튼 → 재처리 모달(§7) 오픈.

## 11. 공통 UX 규칙

- **재처리 유도 패턴 통일**: 데이터에 영향 주는 수정(구조 보정/사전 적용 취소/PII 해제/사전 항목 변경)은 즉시 반영하지 않고 ①기록 → ②하단 배너/다이얼로그로 재처리 제안 → ③사용자가 실행 — 원본 보존·이력 추적 원칙과 일치.
- **딥링크**: 모든 경고/추적 요소(품질 경고, 정제 변경, 청크, 노드)는 관련 탭·원문 위치로 이동 가능해야 한다.
- **진행 표시**: 블록 단위 타임라인을 문서 카드·문서 상세·런 상세에서 동일 컴포넌트로 재사용.
- **권한 게이팅**: 민감정보 원문 열람/승인, 검토 승인, 컬렉션 기본 지정, 컬렉션 재처리는 권한 없는 사용자에게 버튼 비활성 + 사유 툴팁.
- **접근성**: 상태를 색으로만 구분하지 않음(배지 텍스트 병기), diff 뷰는 색상 + 취소선/밑줄 병용.
