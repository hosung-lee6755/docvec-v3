# 전처리 워크플로우 화면 와이어프레임

**최종 갱신**: 2026-11-17. 2026-07-28 와이어프레임을 2026-11-17 코드 점검 결과에 맞춰 고쳤다. 각 화면은 현재 구현된 모습을 텍스트 와이어프레임으로 그리고, 설계와 다른 부분은 "미구현" 또는 "설계와 차이"로 표시했다.

**작성일**: 2026-07-16
**상위 문서**: `전처리_워크플로우_통합_설계서.md` §9, `문서_처리_플랫폼_디자인_설계서.md`
**상태**: 구현 완료. 미구현 항목은 각 절에 표시했다.

## 공통 전제

- 전체 레이아웃은 좌측 사이드바 내비게이션과 콘텐츠 영역으로 이루어진다. 와이어프레임은 콘텐츠 영역만 그린다.
- 폼 컨트롤은 KRDS 기반 컴포넌트(`krds-input`, `krds-form-select`, `krds-form-check`)와 `ds-` 클래스를 쓴다.
- 표기: `[버튼]` 버튼, `(○/●)` 라디오, `[x]` 체크박스, `▾` 드롭다운, `⚠` 경고, `✕` 실패, `✓` 완료, `◐` 처리 중.

## 0. 좌측 메뉴 (현재 구성)

메뉴는 `frontend/src/components/navigation.ts`의 `NAV_GROUPS`가 정의한다. 설계 초안의 "대시보드, 문서 처리, 지식 활용, 구성, 관리" 4그룹은 "워크스페이스, 문서 처리, 지식 활용, 파이프라인 설정, 관리"로 바뀌었다.

```
┌──────────────┐
│ 대시보드      │
│              │
│ 워크스페이스   │  프로젝트, 컬렉션
│              │
│ 문서 처리     │  문서, 검토 대기 [⚠ 3], 실패 [✕ 2], 처리 현황
│              │
│ 지식 활용     │  검색, 채팅
│              │
│ 파이프라인 설정│  워크플로우, 검색 사전 (관리자), 정제 규칙 (관리자)
│              │
│ 관리 (관리자) │  사용자, 그룹, 문서 원천 연결, 외부 에이전트 토큰,
│              │  감사 로그, 답변 추적, AI 기본법 근거 자료, 사용량
└──────────────┘
하단: 계정 설정
```

- 검토 대기와 실패 배지는 상시 표시되며 주기적으로 갱신된다.
- 관리 그룹과 "검색 사전", "정제 규칙" 항목은 관리자에게만 보인다.
- 설계 초안의 "구성" 그룹명과 "사전 관리" 명칭은 현재 "파이프라인 설정"과 "검색 사전"으로 바뀌었다.

## 1. 문서 목록 (`/documents`)

```
┌────────────────────────────────────────────────────────────────────────────────┐
│ 문서                                                           [문서 업로드]    │
├────────────────────────────────────────────────────────────────────────────────┤
│ [파일명 검색________] [상태 ▾] [컬렉션 ▾] [처리 품질 ▾] [기본(이전 버전 숨김) ▾]  │
│                                                  [필터 초기화]                  │
│ ⚠ 검토 대기 문서가 있습니다.  [검토 대기만 보기]                                  │
├────────────────────────────────────────────────────────────────────────────────┤
│ [x] 파일명                 컬렉션    상태            품질             크기  생성일  │
│ [ ] 사업계획서.pdf         기획      ✓ 색인 완료     정상              10.4MB 07-15 │
│ [ ] 계약서_v3.hwp          법무      ⚠ 검토 대기     품질 경고         1.2MB  07-16 │
│ [ ] 매출현황.xlsx          재무      ◐ 청크 분할     -                 0.6MB  07-16 │
│ [ ] 회의록_0710.docx       기획      ✕ 실패          품질 실패         0.8MB  07-14 │
├────────────────────────────────────────────────────────────────────────────────┤
│ [선택 재처리] [선택 삭제]                                 표시 건수 [20 ▾] ‹ 1 ›│
└────────────────────────────────────────────────────────────────────────────────┘
```

- 생성일, 파일명, 파일 크기, 상태를 기준으로 정렬할 수 있다. 열 머리글을 눌러도 정렬된다.
- 상태 필터에는 "검토 대기"와 "실패" 같은 묶음 항목이 있다. 검토 대기 필터 버튼은 `?status=` 쿼리로 목록을 거른다.
- 품질 열에는 종합 점수 대신 품질 판정 라벨이 나온다.
- 행 선택 후 [선택 재처리](실패 블록부터 다시 처리)와 [선택 삭제]를 쓸 수 있다.
- 처리 중인 문서가 있으면 목록을 주기적으로 다시 불러온다.
- 보관된 문서는 "보관됨" 배지가 붙고 검색에 쓰이지 않는다.
- 설계 초안의 "재처리 모달을 행 버튼으로 연다"는 동작은 구현되지 않았다. 재처리는 문서 상세의 재처리 버튼이나 실패 화면에서 한다.

## 2. 업로드 대화 상자

```
┌──────────────────── 문서 업로드 ────────────────────┐
│ [단일 파일] [ZIP 일괄 업로드]                        │
│                                                     │
│  컬렉션          [기획 문서              ▾]         │
│                                                     │
│  전처리 워크플로우 [컬렉션 기본값 사용      ▾]       │
│                   (표준 전처리 또는 PREPROCESS 워크플로우 목록) │
│                                                     │
│  파일   [파일 선택 (PDF, HWP, HWPX, DOCX, XLSX,     │
│          PPTX, TXT, MD, HTML, 이미지)]               │
│         선택된 파일: 사업계획서.pdf, 회의록_0710.docx │
│                                                     │
│  [x] 같은 이름이 있어도 새 문서로 올리기              │
│      (끄면 같은 이름의 문서를 새 버전으로 잇습니다)     │
│  [x] 검토 없이 자동 진행 (파일이 2개 이상이면 자동 적용) │
│                                                     │
│                            [닫기]  [업로드]          │
└─────────────────────────────────────────────────────┘
```

- 드래그 앤 드롭 영역은 없다. 파일 선택 버튼만 쓴다.
- 지원 형식 목록은 `backend/app/pipeline/formats.py`가 정본이다.
- ZIP 탭은 파일을 하나 고르고, 결과를 등록됨, 중복, 건너뜀, 실패 건수로 보여준다.
- 설계 초안의 문서명, 설명, 문서 유형, 태그 입력과 "업로드 시작" 문구는 구현되지 않았다.
- 워크플로우 "변경" 카드 대신 드롭다운을 쓴다.

## 3. 문서 상세 (`/documents/:id`)

```
┌────────────────────────────────────────────────────────────────────────────────┐
│ ← 문서 목록   사업계획서.pdf                              [원본 다운로드] [재처리] │
│ ✓ 색인 완료   [보안 등급 배지]                                                   │
├────────────────────────────────────────────────────────────────────────────────┤
│ 원문 대조 | 구조 | 요소 | 정제 비교 | 사전 적용 | 민감정보 | 청크 | 표 | 그림 |    │
│ RAG 데이터 수정 | 품질 | 처리 이력                                                 │
├────────────────────────────────────────────────────────────────────────────────┤
│                             (선택된 탭 콘텐츠)                                   │
└────────────────────────────────────────────────────────────────────────────────┘
```

- 헤더에는 파일명, 상태 배지, 보안 등급 배지가 나온다. 원본 다운로드는 처리가 끝난 문서에서만 보인다.
- 설계 초안의 헤더 메타 줄(품질 점수, 페이지 수, 청크 수, 워크플로우 버전, 사전 버전)은 구현되지 않았다. 품질 점수는 품질 탭에서, 청크 수는 좌측 RAG 현황 패널에서 본다.
- 탭 표시 조건은 `DocumentDetailPage`의 `TABS`와 `WORKFLOW_TAB_KEYS`를 따른다. 구조, 정제 비교, 사전 적용, 민감정보, 청크, 품질, 처리 이력은 항상 보인다. 요소, 표, 그림, RAG 데이터 수정, 원문 대조는 처리 완료 상태에서 보인다. 요소는 PDF 문서만 보인다.

### 3.1 헤더 아래 검토 대기 배너

```
│ ⚠ 이 문서는 검토 대기 중입니다. 품질 리포트를 확인하고 승인 또는 반려하세요.        │
│                                               [품질 탭으로 이동]                    │
```

- 설계 초안의 "바로 승인" 버튼은 배너에 없다. 승인은 품질 탭이나 검토 대기 화면에서 한다.
- 검토 대기 문서를 열면 품질 탭이 먼저 열린다.

### 3.2 원문 대조 탭

```
├──────────────────────────────┬─────────────────────────────────────────────────┤
│  원본 미리보기               │  추출 텍스트 (쪽 단위)                          │
│ ┌──────────────────────────┐ │ ┌─────────────────────────────────────────────┐ │
│ │   (PDF 페이지 이미지)     │ │ │ 1. 사업 개요                                │ │
│ │                          │ │ │ 본 사업은 문서 기반 AI 플랫폼을 구축하여…   │ │
│ └──────────────────────────┘ │ └─────────────────────────────────────────────┘ │
│  ◀ 12 / 42 ▶                 │                                                 │
└──────────────────────────────┴─────────────────────────────────────────────────┘
```

- 좌측은 원본 쪽 미리보기, 우측은 추출 텍스트다. 쪽을 넘기면 두 영역이 함께 바뀐다.
- 설계 초안의 노드와 청크 span 기반 양방향 하이라이트, OCR 영역 점선 표시, 추출본과 정제본 전환 토글은 구현되지 않았다.

- 설계 초안의 element_id와 bbox 표시, 요소에서 구조 탭 노드로의 역참조는 구현되지 않았다.

### 3.5 정제 비교 탭

```
│ 변경 내역 (규칙별)                                                                   │
│ 규칙              위치        정제 전                  정제 후                    │

- 전후 문장을 나란히 보여준다. 규칙 이름과 위치를 함께 표시한다.
- 설계 초안의 "규칙 관리 링크 표시"와 "이 실행의 규칙 버전" 표시는 구현되지 않았다.

### 3.6 사전 적용 탭

```
│ 적용 내역                                                                            │
│ 유형        원문    적용 결과     위치     사전 항목      상태        작업            │
│ 사용자 사전 국토부  국토교통부    3쪽      (항목 ID)      적용됨      [적용 취소]     │
│ 동의어      AI      인공지능      5쪽      (항목 ID)      적용됨      [적용 취소]     │

- 개별 적용 취소는 표시만 바꾼다. 재처리해야 반영된다.
- 문서 단위 항목 제외 토글은 `dictionary-exclusions` API로 저장된다.
- 설계 초안의 "사전 항목 클릭 시 사전 관리로 이동" 링크는 구현되지 않았다.

### 3.7 민감정보 탭

```
│ 유형          탐지 값(마스킹)     위치     신뢰도  조치      상태          작업        │
│ 전화번호      010-****-5678       8쪽     0.98    마스킹    승인됨        -           │
│ 주민등록번호  8*****-*******      31쪽    0.97    임베딩 제외 대기        [승인] [해제]│
│ 계좌번호      110-***-****56      31쪽    0.85    마스킹    대기          [승인] [해제]│
│                                              [원문 보기] (관리자만 표시)               │
```

- 승인과 해제를 할 수 있다. 원문 보기는 전역 관리자에게만 보이며 감사 로그가 남는다.
- 설계 초안의 "마스킹 미리보기 나란히 비교"와 "일괄 승인" 기능은 구현되지 않았다.
- 설계의 NER 탐지(이름, 주소)는 미구현이라 정규식과 체크섬으로 찾은 항목만 나온다.

### 3.8 청크 탭

```
├──────────────────────────────────────────────┬─────────────────────────────────┤
│ 청크 목록                                     │ 청크 상세                       │
│ #22  1. 사업 개요 > 1.2 목적      598 토큰 12쪽│ 청크 #23, 642 토큰, 12~13쪽      │
│ #23  전처리 > 문서 분할  ✎ 수정됨 642 토큰 12쪽│ 섹션: 문서 데이터 전처리 > 문서 분할 │
│ #24  전처리 > 품질 검증   701 토큰 13쪽        │ 텍스트                           │
│ [검색 제외] 표시 청크 🚫                        │ [텍스트 편집]                   │
│                                              │ [저장 (재임베딩)] [검색 제외]     │
│                                              │ [이전 청크] [다음 청크] [상위 청크 보기] │
└──────────────────────────────────────────────┴─────────────────────────────────┘
```

- 텍스트를 저장하면 재임베딩이 실행된다. 재임베딩은 Qdrant 포인트만 갱신하며 DB 청크 행은 바뀌지 않는다(설계와 차이).
- 검색 제외 토글은 청크를 검색에서 뺀다.
- 설계 초안의 "원문 구간 diff 접기", "청크 경계 수정", "원문 대조에서 하이라이트 연동"은 구현되지 않았다. 원문 쪽 이동 버튼은 있다.
- 품질 경고 대상 청크는 "품질 경고 대상 청크" 표시와 다음 대상 이동 버튼으로 찾는다.

### 3.9 표, 그림, RAG 데이터 수정 탭

- 표 탭: 추출된 표를 보여준다.
- 그림 탭: 추출된 그림과 그림 설명을 보여준다.
- RAG 데이터 수정 탭: 텍스트 리비전 이력(원문, 정제, 사용자 편집 출처)과 원문 편집 영역을 보여준다. 설계 초안의 청크 직접 편집 인터페이스는 청크 탭으로 대체되었다.

### 3.10 품질 탭 (검토 게이트)

```
├────────────────────────────────────────────────────────────────────────────────┤
│  91.5   ⚠ 품질 경고 (검토 대기)                                                    │
│  점수는 어떻게 계산되나요? (산정 기준 보기)                                         │
│  텍스트 추출  ████████░░ 96                                                      │
│  OCR          ███████░░░ 88                                                      │
│  구조         ████████░░ 90                                                      │
│  청크         █████████░ 90                                                      │
│  원문 재현율  ████████░░ 92  (측정할 수 있을 때만)                                   │
├────────────────────────────────────────────────────────────────────────────────┤
│  경고                                                                             │
│  ⚠ 12쪽 OCR 신뢰도가 기준 이하입니다 (0.84)            [원문 대조 탭에서 확인 →]    │
│  ⚠ 표 3개의 구조 복원 결과를 확인해야 합니다            [구조 탭에서 대상 확인 →]    │
│  ⚠ 품질 경고 대상 청크                                  [청크 탭에서 확인 →]        │
├────────────────────────────────────────────────────────────────────────────────┤
│                                              [반려]   [승인 후 계속 진행]           │
└────────────────────────────────────────────────────────────────────────────────┘
```

- 종합 점수는 항목 점수의 평균이다. 청크가 0개이면 평균과 무관하게 실패다.
- 항목 점수는 텍스트 추출, OCR(OCR을 쓴 문서만), 구조, 청크, 원문 재현율(측정할 때만)이다. "정규화" 항목은 항상 100점이라 표시하지 않는다.
- 반려와 승인은 검토 대기 상태에서만 보인다. 승인과 반려는 런 API를 호출한다.
- 설계 초안의 "검토 의견 입력란"과 "실패 페이지 목록" 영역은 구현되지 않았다. 검토 의견 필드가 API에 없다.
- 설계 초안의 "수정 사항이 있어 해당 블록부터 재실행됩니다" 확인 대화 상자는 구현되지 않았다. 승인하면 멈춘 지점부터 이어서 실행한다.

### 3.11 처리 이력 탭

```
│ 실행 이력 (3)                                                                     │
│ ▾ 재처리 (동의어 정규화부터)  2026-11-16 14:02  ✓ 완료  1분 12초                     │
│    ├─ ✓ 파일 검증         캐시     0.0초                                            │
│    ├─ ✓ 텍스트 추출       캐시     0.0초                                            │
│    ├─ ✓ 텍스트 정제       캐시     0.0초                                            │
│    ├─ ✓ 동의어 정규화             2.1초                  [이 블록부터 재처리]      │
│    ├─ ✓ 문서 분할                 4.8초  48청크                                    │
│    ├─ ✓ 품질 검증                 1.2초  점수 91.5, 경고 2                         │
│    └─ ✓ RAG 저장                  8.4초                                            │
│ ▸ 업로드  2026-11-15 11:18  ⚠ 검토 대기 → 재개됨                                    │
│ 스텝을 누르면 입출력 요약과 경고 상세가 열린다.                                       │
```

- 런 헤더에는 실행 종류(업로드, 수동, 재처리, 자동 분석), 시각, 상태, 소요 시간이 나온다.
- 재사용된 스텝, 곧 캐시 히트와 재처리 시 상류 복사 모두에서 cached 값이 true인 스텝은 "캐시" 배지로 표시한다. 실패한 스텝은 ✕와 오류 안내를 보여준다.
- "이 블록부터 재처리"를 누르면 재처리 대화 상자가 시작점이 고정된 상태로 열린다.
- 스텝 상세 패널은 입력과 출력 요약, 해시, 경고를 보여준다.

## 8. 검색 사전 (`/dictionary`, 관리자)

사전 항목을 저장하면 영향 확인 대화 상자(`ImpactModal`)가 열린다.

```
┌──────────── 사전 항목이 저장되었습니다 ────────────┐
│ '국토부 → 국토교통부' 항목이 수정되었습니다.        │
│                                                    │
│ 이 항목이 적용된 문서: 27건                          │
│ 재처리는 문서별로 직접 실행해야 합니다.               │
│                                                    │
│                              [닫기]                 │
└────────────────────────────────────────────────────┘
```

- 자동 재처리 버튼은 없다. 설계 초안의 "27건 재처리" 버튼은 구현되지 않았다.

사전 화면은 불용어, 동의어, 사용자 사전, 버전 이력 탭으로 나뉜다.

```
│ [불용어] [동의어] [사용자 사전] [버전 이력]                                    │
│ ──────────────────────────────────────────────────────────────────────────   │
│ 버전 이력 보기: 번호, 시각, 변경 종류(생성, 수정, 삭제, 가져오기), 작성자          │
```

- 버전 이력 보기는 리비전 목록을 보여준다. 리비전별로 실행된 런 목록을 보여주는 기능은 없다.
- 상단 안내는 검색에 실제 적용되는 규칙이 정규화(KEEP, NORMALIZE)뿐이라고 밝힌다.

## 12. 공통 UX 규칙

- **재처리 유도**: 구조 보정, 사전 적용 취소, 민감정보 해제, 사전 항목 변경은 즉시 재처리하지 않는다. 변경을 기록하고, 재처리가 필요하다는 배너나 안내를 띄운다. 재처리는 사용자가 실행한다.
- **딥링크**: 품질 경고와 검토 대기 항목은 관련 탭(`?tab=`)으로 이동한다. 청크 경고는 청크 탭의 대상 청크로 이동한다.
- **진행 표시**: 블록 단위 타임라인(StepTimeline)을 문서 상세와 런 대화 상자에서 같은 컴포넌트로 보여준다.
- **권한 게이팅**: 원문 열람(관리자), 사전과 정제 규칙 관리(관리자), 검토 승인과 반려, 워크플로우 실행, 재처리(editor 이상)는 권한이 없으면 버튼을 숨기거나 비활성 처리한다.
- **접근성**: 상태는 색과 텍스트를 함께 쓴다. 점수 막대에는 숫자를 함께 쓴다. 아이콘 버튼에는 라벨을 붙인다.
- **미구현 항목**: 끌어다 놓기 업로드, 청크와 노드 경계 수정, 검토 의견 입력, 노드 단위 재처리, 실패율 임계 알림, 컬렉션 재처리 완료 알림은 설계에는 있었으나 구현되지 않았다.
