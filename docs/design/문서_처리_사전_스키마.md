# 문서 처리 사전 스키마

문서 처리용 사전은 **불용어 사전**, **동의어 사전**, **사용자 사전**으로 구분하되, 공통 메타데이터 구조는 통일하여 관리하는 방식을 권장합니다.

---

## 1. 불용어 사전 스키마

문서 분석, 검색, 키워드 추출 과정에서 제외할 단어를 관리합니다.

| 필드명 | 타입 | 필수 | 설명 | 예시 |
|---|---|---:|---|---|
| `stopwordId` | string | Y | 불용어 항목 식별자 | `SW-0001` |
| `word` | string | Y | 제외할 단어 또는 표현 | `그리고` |
| `matchType` | enum | Y | 일치 방식 | `EXACT` |
| `caseSensitive` | boolean | N | 영문 대소문자 구분 여부 | `false` |
| `language` | string | N | 언어 코드 | `ko` |
| `scope` | array | N | 적용 문서 유형 또는 업무 범위 | `["ALL"]` |
| `reason` | string | N | 제외 사유 | `접속사` |
| `enabled` | boolean | Y | 사용 여부 | `true` |
| `createdAt` | datetime | Y | 생성일시 | `2026-07-10T13:00:00Z` |
| `updatedAt` | datetime | Y | 수정일시 | `2026-07-10T13:00:00Z` |

### JSON 예시

```json
{
  "stopwordId": "SW-0001",
  "word": "그리고",
  "matchType": "EXACT",
  "caseSensitive": false,
  "language": "ko",
  "scope": ["ALL"],
  "reason": "문서 분석 시 의미 기여도가 낮은 접속사",
  "enabled": true,
  "createdAt": "2026-07-10T13:00:00Z",
  "updatedAt": "2026-07-10T13:00:00Z"
}
```

### `matchType` 권장 값

| 값 | 설명 |
|---|---|
| `EXACT` | 단어가 정확히 일치할 때 제외 |
| `CONTAINS` | 해당 문자열을 포함하면 제외 |
| `PREFIX` | 해당 문자열로 시작하면 제외 |
| `SUFFIX` | 해당 문자열로 끝나면 제외 |
| `REGEX` | 정규식 기준으로 제외 |

## 2. 동의어 사전 스키마

서로 다른 표현을 하나의 대표 용어로 정규화하거나, 검색 시 동일한 의미로 확장하기 위한 사전입니다.

| 필드명 | 타입 | 필수 | 설명 | 예시 |
|---|---|---:|---|---|
| `synonymId` | string | Y | 동의어 그룹 식별자 | `SY-0001` |
| `canonicalTerm` | string | Y | 대표 용어 | `인공지능` |
| `synonyms` | array | Y | 동의어 및 변형 표현 | `["AI", "인공 지능"]` |
| `direction` | enum | Y | 동의어 적용 방향 | `ONE_WAY` |
| `processingMode` | enum | Y | 처리 방식 | `NORMALIZE` |
| `caseSensitive` | boolean | N | 영문 대소문자 구분 여부 | `false` |
| `language` | string | N | 언어 코드 | `ko` |
| `scope` | array | N | 적용 범위 | `["ALL"]` |
| `description` | string | N | 동의어 그룹 설명 | `AI 관련 표현 통합` |
| `enabled` | boolean | Y | 사용 여부 | `true` |
| `createdAt` | datetime | Y | 생성일시 |  |
| `updatedAt` | datetime | Y | 수정일시 |  |

### JSON 예시

```json
{
  "synonymId": "SY-0001",
  "canonicalTerm": "인공지능",
  "synonyms": [
    "AI",
    "A.I.",
    "인공 지능",
    "Artificial Intelligence"
  ],
  "direction": "ONE_WAY",
  "processingMode": "NORMALIZE",
  "caseSensitive": false,
  "language": "ko",
  "scope": ["ALL"],
  "description": "인공지능 관련 표현을 대표 용어로 통합",
  "enabled": true,
  "createdAt": "2026-07-10T13:00:00Z",
  "updatedAt": "2026-07-10T13:00:00Z"
}
```

### `direction` 권장 값

| 값 | 설명 |
|---|---|
| `ONE_WAY` | 동의어를 대표 용어로만 변환 |
| `BIDIRECTIONAL` | 그룹 내 모든 용어를 서로 동의어로 인식 |

### `processingMode` 권장 값

| 값 | 설명 |
|---|---|
| `NORMALIZE` | 내부 분석 시 대표 용어로 통합 |
| `REPLACE` | 실제 문서 텍스트를 대표 용어로 치환 |
| `SEARCH_EXPAND` | 검색 시 동의어를 함께 검색 |
| `TAGGING` | 동일 개념 태그를 부여 |

## 3. 사용자 사전 스키마

도메인 전문용어, 기관명, 제품명, 약어, 고유명사 등 사용자가 직접 정의한 용어를 관리합니다.

| 필드명 | 타입 | 필수 | 설명 | 예시 |
|---|---|---:|---|---|
| `termId` | string | Y | 사용자 용어 식별자 | `UD-0001` |
| `term` | string | Y | 표준 용어 | `LangGraph` |
| `variants` | array | N | 오탈자, 띄어쓰기, 별칭 | `["랭그래프"]` |
| `termType` | enum | Y | 용어 유형 | `PRODUCT` |
| `definition` | string | N | 용어 정의 | `그래프 기반 AI 워크플로우 프레임워크` |
| `processingRule` | enum | Y | 처리 규칙 | `KEEP` |
| `pronunciation` | string | N | 발음 또는 읽기 정보 | `랭그래프` |
| `caseSensitive` | boolean | N | 대소문자 구분 여부 | `true` |
| `language` | string | N | 언어 코드 | `en` |
| `scope` | array | N | 적용 범위 | `["요구사항 정의서"]` |
| `metadata` | object | N | 확장 속성 | `{}` |
| `enabled` | boolean | Y | 사용 여부 | `true` |
| `createdAt` | datetime | Y | 생성일시 |  |
| `updatedAt` | datetime | Y | 수정일시 |  |

### JSON 예시

```json
{
  "termId": "UD-0001",
  "term": "LangGraph",
  "variants": [
    "랭그래프",
    "Lang Graph"
  ],
  "termType": "PRODUCT",
  "definition": "그래프 기반 AI 에이전트 및 워크플로우 구성 프레임워크",
  "processingRule": "KEEP",
  "pronunciation": "랭그래프",
  "caseSensitive": true,
  "language": "en",
  "scope": [
    "요구사항 정의서",
    "기술 설계서"
  ],
  "metadata": {
    "category": "AI_FRAMEWORK",
    "referenceUrl": null
  },
  "enabled": true,
  "createdAt": "2026-07-10T13:00:00Z",
  "updatedAt": "2026-07-10T13:00:00Z"
}
```

### `termType` 권장 값

- `TECHNICAL_TERM`: 전문용어
- `ABBREVIATION`: 약어
- `ORGANIZATION`: 기관명
- `PERSON`: 인명
- `PRODUCT`: 제품 또는 서비스명
- `PROJECT`: 프로젝트명
- `POLICY`: 정책 또는 제도명
- `CUSTOM`: 사용자 정의 유형

### `processingRule` 권장 값

- `KEEP`: 원문 유지
- `NORMALIZE`: 변형 표현을 표준 용어로 인식
- `REPLACE`: 실제 텍스트 치환
- `TAG`: 용어 유형 태그 부여
- `EXTRACT`: 주요 개체로 추출
- `MASK`: 민감정보 마스킹
- `IGNORE`: 처리 대상에서 제외

## 4. 통합 사전 관리 스키마

세 종류의 사전을 하나의 사전 관리 단위로 묶는 상위 스키마입니다.

```json
{
  "dictionaryId": "DICT-0001",
  "dictionaryName": "공통 문서 처리 사전",
  "dictionaryType": "USER",
  "version": "1.0.0",
  "description": "요구사항 및 기술 문서 처리용 사전",
  "ownerId": "USER-0001",
  "scope": {
    "workspaceIds": ["WS-0001"],
    "documentTypes": [
      "REQUIREMENT",
      "TECHNICAL_DESIGN"
    ]
  },
  "priority": 100,
  "enabled": true,
  "entries": [],
  "createdAt": "2026-07-10T13:00:00Z",
  "updatedAt": "2026-07-10T13:00:00Z"
}
```

### `dictionaryType` 권장 값

```text
STOPWORD
SYNONYM
USER
```

## 5. 관계형 데이터베이스 권장 구조

실제 구현에서는 사전별 테이블을 완전히 나누기보다, 공통 상위 테이블과 유형별 상세 테이블을 사용하는 방식이 적절합니다.

### `dictionary`

```text
dictionary_id
dictionary_name
dictionary_type
version
description
owner_id
priority
enabled
created_at
updated_at
```

### `dictionary_entry`

```text
entry_id
dictionary_id
primary_term
entry_type
language
case_sensitive
match_type
processing_rule
scope_json
description
enabled
created_at
updated_at
```

### `dictionary_term_variant`

```text
variant_id
entry_id
variant_term
variant_type
sort_order
enabled
created_at
```

### 사전 유형별 매핑

| 사전 유형 | `primary_term` | `variant_term` |
|---|---|---|
| 불용어 | 제외 대상 단어 | 보통 사용하지 않음 |
| 동의어 | 대표 용어 | 동의어 목록 |
| 사용자 사전 | 표준 용어 | 별칭, 약어, 오탈자, 표기 변형 |

## 6. 엑셀 업로드 형식

### 불용어 사전

```text
단어 | 일치방식 | 대소문자구분 | 언어 | 적용범위 | 제외사유 | 사용여부
그리고 | EXACT | N | ko | ALL | 접속사 | Y
```

### 동의어 사전

```text
대표용어 | 동의어 | 적용방향 | 처리방식 | 대소문자구분 | 언어 | 적용범위 | 사용여부
인공지능 | AI;A.I.;인공 지능 | ONE_WAY | NORMALIZE | N | ko | ALL | Y
```

### 사용자 사전

```text
표준용어 | 변형표현 | 용어유형 | 처리규칙 | 정의 | 대소문자구분 | 언어 | 적용범위 | 사용여부
LangGraph | 랭그래프;Lang Graph | PRODUCT | KEEP | AI 워크플로우 프레임워크 | Y | en | 기술설계서 | Y
```

## 7. 설계 원칙

동의어 사전과 사용자 사전의 역할은 명확히 구분해야 합니다.

- **동의어 사전**: 의미적으로 동일하거나 유사한 표현을 대표 용어로 통합
- **사용자 사전**: 도메인 용어의 인식, 보존, 추출, 태깅, 치환 규칙을 관리
- **불용어 사전**: 분석이나 검색에서 의미 기여도가 낮은 표현을 제외

공통 스키마를 사용하되, 사전 유형별로 필요한 속성만 활성화하는 방식이 관리와 확장에 유리합니다.
